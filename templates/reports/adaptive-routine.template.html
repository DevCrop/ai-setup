이 루틴의 ‘학습’은 검증된 피드백을 기록하고 지침·운영 절차를 갱신하는 것입니다. 모델의 가중치 재학습이나 자아를 만드는 기능은 아니며, 모든 대화 접근·모든 세션의 지침 준수를 보장하지 않습니다.

개선이 이루어지는 과정

피드백 → 판단 → 수정 → 검증
01 · CAPTURE

의도와 피드백 기록

사용자의 명시적 선호·수정 요청과 실제 작업에서 관찰한 실패만 요약합니다. 범위·날짜·근거를 붙이며, 추측은 확인된 선호로 승격하지 않습니다.

사용자 확인가설은 후보
02 · DIAGNOSE

문제의 원인 구분

지침 누락, 기존 규칙 미준수, 도구·환경 결함, 접근·권한 한계, 요구 충돌을 나눕니다. 이미 있는 규칙을 따르지 않은 문제에 같은 문장을 덧붙이지 않습니다.

원인 먼저중복 제거
03 · REVIEW

공식 근거와 적용성 확인

관련 공식 원문과 실제 설치 상태를 대조합니다. 구독·클라이언트·Windows 적용성을 확인하고, API 사례나 다른 모델의 성과를 현재 셋업의 성능으로 옮기지 않습니다.

관련 본문 검토변경된 근거만
04 · CHANGE

가장 작은 개선 적용

기존 도구·검사를 재사용하고, 글로벌 개인 선호와 프로젝트 규칙을 제자리에 둡니다. 소유권·사용자 편집·충돌·복구점을 확인한 승인 범위만 수정합니다.

승인 범위최소 변경
05 · VERIFY

실제 결과로 확인

파일 무결성·관련 실행·최종 diff를 확인합니다. 설치 성공, 스킬 호출, 모델 행동, RTK 추정치와 OpenAI 실제 사용량은 서로 다른 증거로 취급합니다.

영향받은 검사원본 증거
06 · DECIDE

유지·보류·복구 후 종료

완료 조건을 충족하면 끝냅니다. 실패하면 복구·검증하고, 새 근거 없이 같은 시도를 반복하지 않습니다. 의미 있는 개선·새 실패·필요 결정만 알립니다.

변경 없으면 유지실패는 성공 아님

언제 점검하고 언제 대응하나

정기 + 진행 중 관찰

새 버전 확인과 실제 설치를 분리합니다. 사용 이벤트마다 업데이트하거나 전체 검사를 반복하지 않습니다.

대상시점처리분류

관찰 대응은 현재 승인된 작업에서 발생한 문제를 처리하는 것입니다. 상시 이벤트 감시 서비스·새 훅·다른 대화 탐색을 설치하지 않습니다.

구분배운 내용 · 적용 범위근거와 다음 행동상태

규칙으로 채택하는 기준

명시적으로 지속 사용을 요청한 선호는 확인 상태로 기록합니다. 반복된 검증 가능한 문제는 기존 규칙·도구와 비교한 뒤 가장 좁은 위치에 반영합니다. 일회성 실수·추정 선호는 후보로 두며, 새 근거나 사용자 확인이 있어야 채택합니다.

누적하는 대신 정리하기

같은 교훈은 기존 ID에 합칩니다. 사용자의 후속 수정은 해당 선호를 대체하고 짧은 사유만 남깁니다. 오래된 지침은 충돌·회귀 검토 후 정리합니다. 더 많은 규칙이나 매일 수정한 줄 수를 성과로 보지 않습니다.

브라우저·앱을 사용하는 방식

공식 실행 도구 · 개인 워크플로

요청한 브라우저와 탭을 먼저 따릅니다. 세 경로의 검증 결과는 각각 기록합니다.

프로젝트 공통 적용
개인 스킬 computer-use-workflow는 Projects·ChatGPT·셋업 저장소에서 발견을 확인했습니다. 작업 폴더마다 복사하거나 도구를 다시 설치할 필요가 없습니다. 실제 실행은 현재 세션에서 제공되는 공식 도구를 사용합니다.

오류를 기록하고 다음 작업에 반영하기

증상 · 발생 단계 · 시도한 복구 · 확인된 결과 · 다음 검사 조건을 같은 기록에서 관리합니다.

저장하는 정보

브라우저/앱 구분, 정제된 오류 서명, 발생·복구·검증 시각, 확인 가능한 도구 식별자, 결과와 재검토 조건을 기록합니다. 같은 문제는 기존 ID에 합칩니다.

수집 범위

현재 승인된 작업에서 실제 관찰한 오류만 기록합니다. 원문 화면·명령 이력·프롬프트·비밀·브라우징 기록을 복제하지 않습니다. 성공한 경로와 접근 불가능한 대상을 별도로 표시합니다.

최종 작업 FLOW · 개선 루틴

작업은 즉시 완료하고, 매일 쌓인 근거로 운영 방식을 개선합니다. 현재 호스트의 확인된 기록을 근거로 갱신합니다.

작업할 때

승인된 활성 프로젝트

01 · 의도와 경계

요청 결과·실제 작업 루트·글로벌/프로젝트 지침·최소 완료 기준을 확인합니다.

02 · 도구 선택

목적에 맞는 사용 가능한 도구·연결·스킬을 선택합니다. RTK는 지원 진단마다, Ponytail·Archify는 명시 요청 시 사용합니다.

03 · 실행과 복구

필요한 최소 작업을 수행합니다. 오류는 원인을 구분해 기록하고 승인된 수정은 즉시 끝냅니다. 같은 실패를 근거 없이 반복하지 않습니다.

04 · 확인과 완료

원래 실패 경로·영향받은 검사·diff를 확인합니다. 실제 통과한 범위를 보고하고 완료 기준에 도달하면 종료합니다.

등록된 정기 점검

현재 호스트 일정 · 등록 여부 확인

01 · 관련 근거 수집

공식 업데이트·RTK 일별 집계·허용된 작업의 새 오류/교정·미해결 후보를 확인합니다. 전체 대화나 프로젝트는 탐색하지 않습니다.

02 · 회고와 판단

확인된 선호·실제 설치·보고서와 대조합니다. 모순·오래된 권고·도구 누락을 찾아 유지/적용/보류/미확인으로 결정합니다.

03 · 최소 개선

승인 범위의 필요한 호환 변경만 복구점을 확보해 적용합니다. 원인 결함은 실제로 고치고, 바꿀 이유가 없으면 유지합니다.

04 · 검증과 환류

영향받은 검사·실제 파일·재적용을 확인합니다. 결정 기록과 보고서를 갱신하고 다음 작업/점검에 연결합니다.

변경 없음 / 같은 근거미검토·보류 건 확인 → 기존 검토·성공 증거 재사용 → 실제 집계 갱신 → 조용히 종료
충돌 / 승인 밖 / 정책 차단적용 보류 → 영향·필요 조치·재검토 조건 기록 → 새 위험·최소 필요 결정만 알림
검사 실패 / 결과 불명확실제 상태 확인 → 허용된 수정 또는 복구 → 원래 경로 재검증. 복구 실패는 미완료로 보고
완료 / 게시 전reviewed → applied → verified를 실제 증거로 구분. committed/published는 별도이며 미게시 변경을 배포 완료로 표시하지 않음

    상황별 도구 선택 기준

    필요한 최소 경로
    상황우선 경로전환·종료 조건
    간단한 질문·작은 수정직접 처리 관련 파일·최소 도구충분한 근거와 완료 조건을 확인하면 종료. 불필요한 스킬·문서·위임을 늘리지 않습니다.
    지원되는 필요한 진단 · 매 호출TRACE RTK 러너 소유·해시 검사 후 필터중첩 Python/PowerShell도 러너를 직접 호출합니다. 절감 0도 정상이며 원문·JSON·변경·최종 검증은 native로 유지합니다.
    구현 선택·재사용 판단기존 코드·표준 기능 Ponytail은 명시 요청 시요청 기능·오류 처리·보안·검증을 보존하면서 가장 작은 구현을 선택합니다.
    흐름·분기·예외 확인실제 소스와 계약 Archify는 명시 요청 시성공 경로뿐 아니라 변경 없음·승인 밖·충돌·복구 실패·종료까지 확인합니다.
    공식 절차와 현재 상태 불일치공식 원문 + 설치 증거지원 여부·버전·권한·환경·요구를 구분. 허용된 호환 수정은 검증까지 끝내며 접근 실패는 미확인으로 둡니다.
    실패 반복·검증 미완료가설 재검토 · 원본 검사동일한 실패를 그대로 재시도하지 않습니다. 필요한 복구와 정확한 결정·외부 제약을 먼저 보고합니다.

    도구 선택은 로컬 운영 정책입니다. RTK·Ponytail·Archify는 제3자 구성이고 OpenAI의 기능·권한과 구분합니다.

    자동 적용과 검증 경계

    기존 호스트 승인 보존

    매일 승인 범위에서 처리

    작은 호환 지침안정 CLI·RTK현재 보고서 갱신

    변경된 관련 공식 내용과 새 피드백을 검토하고, 소유권·충돌·복구점·검사를 통과한 변경만 적용합니다. 이미 검토한 근거는 재사용합니다. 변경이 필요하지 않으면 기존 구성을 유지합니다.

    별도 결정을 필요한 상태로 남김

    새 플러그인·권한모델·effort 변경실행 로직·큰 구조GitHub 원격 게시

    피드백이나 공식 아티클은 실행 권한을 넓히지 않습니다. 자동 승인 차단을 우회하지 않으며, 필요한 경우 검토 가능한 변경안과 가장 작은 결정만 요청합니다.

    이번 설정의 완료 상태

    단계·검사실제로 확인한 내용상태
    일정·가용성과 다른 세션의 범위

    현재 호스트의 기존 heartbeat 일정·스레드·알림 동작을 유지합니다. PC와 앱이 사용 가능한 때만 로컬 작업을 수행할 수 있습니다. 저장된 일정은 미래 실행 완료의 증거가 아닙니다. 다른 세션은 설치된 글로벌 지침을 물려받지만 모든 과거 대화가 자동 제공되지는 않습니다. 새로운 선호가 현재 승인된 맥락에서 기록되지 않았다면 이 루틴이 아는 것으로 간주하지 않습니다. 별도 node_modules 주간 정리의 승인된 기준·보호 프로젝트는 유지합니다.

    효율은 어떻게 판단하나

    정답성·요청 기능·검증 완료·사용자 제약을 먼저 지키고, 그 안에서 탐색량·도구 호출·중복 검사·출력 크기를 줄입니다. RTK 기록은 추정 토큰과 실제 바이트 비교에만 사용합니다. 전체 업무 시간·정확도·OpenAI 토큰 절감은 측정되지 않았으며 ‘항상 최고의 성능’으로 표시하지 않습니다. 수치를 만들기 위한 반복 실행이나 모델/API 벤치마크는 하지 않습니다.

    공식 근거와 로컬 정책

    관련 본문 검토 기록

    공식 근거는 피드백·간결한 지침·일정·관련 검증을 뒷받침합니다. 현재 ledger 구조·승인 경계·도구 선택·보고 UI는 이 사용자의 로컬 운영 정책입니다.
