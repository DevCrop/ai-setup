# Spec: Claude Monitor (데스크톱 앱)

## Goal
Claude Code와 Codex의 이 PC 설정을 자동으로 살펴, 작업 중에도 작업 표시줄 위 작은 상태 막대로 상태를 보여 주고, 누르면 앱 창(브라우저 아님)에서 자세히 보고 필요 없는 설정을 정리할 수 있게 한다. 어느 PC든 `bootstrap/setup.ps1` 한 번으로 같은 앱이 깔린다.

## Users and scope
- 사용자: 이 저장소 주인 한 명, 여러 Windows PC.
- 앱 이름: Claude Monitor. 위치: 저장소 `app/`. Electron(버전 고정) + Node 20 이상.
- v1 범위는 아래 "Requirements"의 v1 항목. "later"는 이번에 만들지 않고 확장 지점만 남긴다.

## Requirements (사용자 요청 8가지 → 버전)
1. Claude·Codex 내부 설정 자동 모니터링 — v1. Claude는 기존 `scripts/monitor.mjs`의 `collect()`를 그대로 쓴다. Codex는 `~/.codex`를 읽기 전용으로 본다.
2. 필요·불필요 설정 점검 후 최적화 — v1: 점검(Check)이 발견(Finding)을 내고, 고칠 수 있는 것은 고침(Fix)을 제안한다. 자동 실행은 없다. 한 번에 하나, 미리보기 → 사용자가 누름 → 적용 → 되돌리기.
3. 작업 표시줄 위 상태 막대 — v1.
4. 앱 안의 깔끔한 화면 — v1: 기존 모니터 화면(7개 탭)을 앱 창 안에 보여 주고, 새 "최적화" 탭을 더한다. 1300줄짜리 기존 화면은 다시 쓰지 않는다.
5. 필요한 설정을 지금보다 고도화 — v1은 점검 목록(아래)까지. 새 권장 설정 자동 제안은 later.
6. 다른 PC에서도 — v1: bootstrap 모듈 하나로 설치·로그인 자동 시작.
7. 객체지향 — v1: Source, Check, Finding, Fix, Optimizer 클래스(`docs/arch-claude-monitor.md`의 UML이 기준).
8. 확장 고려 — v1: 새 점검은 `app/core/checks/`에 파일 하나 + 레지스트리 한 줄. 새 데이터 출처(Source)도 같은 방식.

## Screens
- Strip (상태 막대): 테두리 없는 작은 창, 항상 위, 작업 표시줄에 안 보임, 작업 영역 오른쪽 아래에 붙음, 끌어서 옮길 수 있음. 보이는 것: 상태 점과 글자(정상 / 확인 필요 N / 문제 N / 모니터 멈춤 / 수집 오류 / 시작 중), 라우팅 일치 a/b, 오늘 출력 토큰, 실행 중 세션·에이전트 수, Codex 상태 한 칸, 마지막 갱신 시각. 누르면 Main 창. 오른쪽 클릭 메뉴: 열기, 지금 새로 읽기, 오른쪽 아래로, 끝내기.
- Main (앱 창): 앱 제목 "Claude Monitor", 작업 표시줄 아이콘 있음. 탭: 기존 7개 + "Codex" + "루틴" + "최적화".
  - Codex 탭: 모델·추론 강도·승인·샌드박스 설정, 켜진 플러그인·MCP 수, 신뢰 프로젝트 수(없는 경로 수), 최근 7일 세션 수, 백업 파일 수.
  - 루틴 탭: Claude와 Codex가 정해진 때 저절로 도는 것만 한 화면에 모은다. 맨 위 요약 칸(Claude 예약 작업 수, Codex 자동화 켜짐/전체, Claude·Codex를 실행하는 Windows 예약 작업 수와 실패 수, 시작 프로그램 켜짐/전체), 그 아래 네 칸: Claude 예약 작업(이름과 설명), Codex 자동화(이름, 상태, 일정, 종류, 바뀐 때), Windows 예약 작업과 시작 프로그램(명령에 claude 나 codex 가 들어 있는 것만).
  - 최적화 탭: 발견 목록(심각도, 출처 Claude/Codex, 제목, 설명, 근거). 고칠 수 있는 항목은 "미리보기" → 바뀔 내용(diff) → "적용" → 적용 뒤 "되돌리기".
- 상태별 모습: 정상, 경고, 문제, 데이터 없음, 모니터 멈춤(갱신이 3주기 넘게 없음), 수집 오류(연속 3회 실패), 적용 중, 적용 실패, 발견 0건. (Electron이 자기 Node로 돌기 때문에 "node 없음" 상태는 없다.)

## Checks v1
Claude (출처 `collect()` 결과와 저장소):
- C1 설정 드리프트: 저장소 `claude/`와 `~/.claude`가 다름 → 고침: `bash scripts/apply.sh`(저장소 → 라이브, 허용된 방향).
- C2 라우팅 불일치: 최근 7일 에이전트가 기대 모델과 다른 모델로 실행 → 보고만.
- C3 모니터 구역 경고/없음(플러그인, 훅, claude-mem, RTK) → 보고만, 다음 할 일 문장 포함.
- C4 라이브에만 있는 설정 키(저장소에 없는 `settings.json` 키) → 고침: 비밀 의심 키와 `env` 등을 뺀 키를 저장소 `claude/settings.json`에 추가(라이브는 안 씀, 되돌리기 가능). 가져올 키가 없으면 보고만. Claude 설정을 고치는 제안은 항상 "저장소 `claude/` 변경"으로 표시하고 라이브 파일은 직접 고치지 않는다.
- C5 없는 훅 스크립트(`settings.json` 훅이 가리키는 스크립트 파일이 없음) → 보고만.
- C6 낮은 캐시 적중률: 최근 7일 출력의 10% 이상, 5만 토큰 이상을 쓴 역할·모델 계열의 캐시 적중률이 50% 미만 → 보고만(정보).
- C7 메인 모델 불일치: 최근 7일 메인 대화 메시지의 20% 이상이 라이브 `settings.json` 모델 계열이 아님 → 보고만(정보).
- C8 에이전트 사용: 저장소에 모델이 정해진 에이전트 중 7일간 한 번도 안 쓴 것, 모델이 정해지지 않은 채 Opus·Fable 로 돈 에이전트 → 보고만(정보).
- C9 하루 토큰 급증: 오늘 출력이 10만 토큰 이상이고 이전 날(3일 이상) 중앙값의 3배 이상 → 보고만(정보).
- C10 큰 컨텍스트: 지금 작업 중인 세션(2분 안에 메시지)의 마지막 프롬프트가 20만 토큰 이상 → 주의(warn), `/compact` 또는 `/clear` 안내. 프로젝트 폴더 이름(basename)마다 하나.
- C11 TokenEconomizer 제안: 훅이 Python 을 매번 찾음(`TE_PYTHON` 없음), 도구 정리 제안이 대기 중, 플러그인 자체 비용이 5% 초과 → 보고만(정보), 명령 하나씩 안내.
C6–C9, C11 는 토큰 수와 모델 이름만 읽고 대화 내용은 읽지 않는다. 정보 등급이라 상태 막대와 점수에 영향이 없다.
하루 요약 알림(2026-10-31 추가): 18시 이후 첫 갱신에 하루 한 번, 오늘 출력이 있을 때만 "프로젝트 N곳 · 출력 · 캐시로 아낀 입력 · 개선 제안 N건"을 보낸다. 숫자만 담고, 알림 끔과 조용한 시간을 따른다. 개요 탭 맨 위 "오늘 작업" 카드는 프로젝트 폴더별 세션, 출력, 캐시로 아낀 입력, 지금 작업 중 여부와 컨텍스트 크기를 보여 준다.
Codex (출처 `~/.codex`):
- X1 없는 경로의 신뢰 프로젝트(`[projects.'<path>']` 경로가 사라짐, 임시 폴더 포함) → 고침: 그 표(헤더와 그 아래 키 줄)만 지움.
- X2 오래된 설정 백업 파일(`config.toml.bak*`가 3개 이상) → 보고만.
- X3 큰 로그 DB(`logs_*.sqlite`가 500MB 이상) → 보고만.
- X4 없는 파일을 가리키는 훅 상태(`[hooks.state.'<key>']`) → 고침: 그 표만 지움(백업, 되돌리기).
- X5 켜졌지만 `command`도 `url`도 없는 MCP 서버 → 보고만.
- X6 worktree가 20개 이상이거나 30일 넘은 것이 있음 → 보고만.
업데이트 (출처 `updates`, 6시간마다, 실패하면 30분 뒤 다시, 설정에서 끌 수 있음, 2026-10-31 추가):
- U1 Claude Code 새 버전: 설치된 `claude --version`이 `autoUpdatesChannel`에 맞는 npm 태그(`latest`/`stable`)보다 낮음 → 보고만(info), 명령 `claude update` 표시. 알림은 보내지 않는다.
- U2 저장소가 원격보다 뒤처짐: `main`이 체크아웃돼 있을 때만, `git ls-remote origin refs/heads/main`의 커밋이 로컬 `HEAD`에 없음(다른 브랜치면 보고 안 함) → 보고만(info), 명령 `git pull` 다음 `bash scripts/apply.sh` 표시.
- 플러그인 핀 불일치는 새 점검을 만들지 않고 C3:plugins의 근거에 "이름 설치 버전 → 핀"과 명령 `bash scripts/install-plugins.sh`을 보탠다.
- 자동 실행은 없다: 앱은 `apply.sh`, `git pull`, 플러그인·Claude Code 업데이트를 스스로 돌리지 않는다.

## 건강 점수와 알림 (2026-10-31 추가)
- 건강 점수: 100에서 문제 1건마다 15, 주의 1건마다 5를 빼고 0..100으로 자른다. 정보·정상은 빼지 않는다. 시작 중·멈춤·데이터 없음·수집 오류일 때는 점수 없음. 최적화 탭 맨 위에 점수, 한 줄 문장, "지금 최적화" 버튼(기존 최적화하기 미리보기를 연다).
- 안정된 발견만 센다: 발견이 처음 보인 뒤 3분(C1은 30분) 동안 계속 보여야 상태 막대의 "확인 필요 N"·"문제 N", 상태, 점수, 알림에 들어간다. 짧게 깜빡이는 발견은 목록에만 보인다. 앱을 다시 켜면 다시 기다린다(꺼져 있던 시간은 센 시간이 아님). 출처를 한 번 못 읽은 실행은 기다린 시간을 지우지 않는다.
- 알림: 안정된 주의·문제 발견만. 같은 발견은 24시간(C2는 7일)에 한 번, 단 심각도가 오르면 다시. 알림은 한 시간에 최대 한 번, 모인 것을 한 번에. 조용한 시간(예 22:00–07:00, 자정을 넘어도 됨)에는 보내지 않고 다음으로 미룬다. 수집 오류 알림은 그대로(연속 오류마다 한 번). 알림 끄기와 조용한 시간은 수집 오류 알림에도 적용된다. 알림 기록 `userData/notify-state.json`에는 알린 발견 id와 시각만 둔다.
- 설정 `userData/settings.json`: 알림 켜기/끄기, 조용한 시간 시작·끝, 업데이트 확인 켜기/끄기. 최적화 탭의 작은 설정 칸에서 바꾼다.
- 화면 테마(2026-10-31 추가): 시스템·라이트·다크. 상단 오른쪽 전환 버튼으로 바꾸고 `settings.json`의 `theme`에 저장한다. 모든 창과 모니터 화면이 함께 바뀐다.
- 보이는 모양(2026-10-31): 점 격자 바탕, 고정폭 숫자, 눈금 막대 미터(개요·절감 KPI, 사용량 막대), 밑줄 탭, 최적화 점수는 눈금 게이지. 앱 아이콘은 `app/assets/icon.svg`(유리 렌즈·눈금·스파크), `app/tools/make-icon.mjs`로 png·ico를 만든다.

## 루틴 (2026-10-31 추가)
- 범위: Claude와 Codex의 루틴만. 다른 프로그램의 예약 작업, 시작 프로그램, 서비스는 보이지 않는다.
- 보고만 한다. 켜기·끄기·삭제 버튼이 없고, 발견(Finding)을 만들지 않으며 건강 점수·상태 막대·알림에 영향이 없다.
- 모으는 방법: 10분마다 뒤에서 한 번. 화면은 마지막 결과를 바로 보여 주고 기다리지 않는다.
  - Claude: `~/.claude/scheduled-tasks/*/SKILL.md` 앞 2KB의 머리말에서 `name`, `description`만. 본문은 읽지 않는다. 일정과 실행 기록은 Claude 앱 안에 있어 보여 주지 않는다.
  - Codex: `~/.codex/automations/*/automation.toml`의 맨 위 키 `id`, `name`, `kind`, `status`, `rrule`, `updated_at`만. `prompt`와 `target_thread_id`는 건너뛰고, 여러 줄 문자열 안의 줄은 키로 읽지 않는다. 세션 파일, `auth.json`, 비밀 폴더는 열지 않는다.
  - Windows(Windows에서만): PowerShell 스크립트 한 번(`Schedule.Service` COM, `Win32_StartupCommand`, `StartupApproved` 레지스트리). 이름·경로·명령 전체에 `claude` 나 `codex` 가 낱말로 들어간 예약 작업과 시작 프로그램만 고른다. 다른 OS에서는 "Windows에서만"이라고 쓰고 PowerShell을 실행하지 않는다.
- 개인정보: 명령의 인수는 절대 보내지 않고 실행 파일 이름만(따옴표 없이 공백이 든 경로는 .exe 같은 아는 확장자까지만 자르고, 확장자가 없으면 이름도 버린다). 이름과 경로, Claude·Codex 루틴 이름과 설명의 SID(`S-1-5-21-…`)와 사용자 이름은 가린다. Codex 파일은 여러 줄 문자열(`"""`, `'''`) 안의 줄을 키로 읽지 않고, 들여쓰거나 점·따옴표가 든 키는 건너뛴다. 작성자는 모으지 않고, 실행 계정은 SYSTEM / 서비스 / 사용자 세 가지로만.
- 실패 판단: 마지막 결과가 오류 비트가 켜진 코드(0x8…, 0xC…)이거나 일반 종료 코드(1..0xFFFF)면 실패. 0, 실행 중(0x41301), 아직 안 돔(0x41303), 대기(0x41325), 0x4…로 시작하는 알림 코드는 실패가 아니다. 꺼진 작업은 실패로 세지 않는다. 결과 코드는 16진수 그대로 보인다.

## Safety rules
- 읽지 않는 것: `.credentials*`, `.env*`, `~/.codex/auth.json`, `~/.codex/secrets/`, `~/.codex/.sandbox-secrets/`, 키·토큰 값. Codex 세션은 개수·모델·시각만 센다(본문 금지).
- Codex 고침: 미리보기 diff, 항목마다 사용자 클릭, 적용 전 `~/.codex/backups/claude-monitor/<시각>-config.toml` 백업, 되돌리기 한 번 클릭. 항목을 골라 한 번에 미리 보고 적용하는 "최적화하기"는 있다(항목마다 백업·되돌리기).
- Claude 고침은 저장소에서 `apply.sh`를 돌리는 것(C1)과 저장소 `claude/settings.json`에 키를 넣는 것(C4)뿐. 라이브 `~/.claude`를 직접 쓰지 않는다.
- Electron: contextIsolation 켜기, nodeIntegration 끄기, IPC 계약과 똑같은 좁은 preload API, 화면은 로컬 파일만 읽음(렌더러 CSP `connect-src 'none'` 그대로), CSP, 단일 인스턴스.
- 네트워크: 업데이트 확인(U1·U2)만, 메인 프로세스에서만. `https://registry.npmjs.org`에 HTTPS GET(5초 제한, 버전 문자열은 semver 모양만 받음)과 `git ls-remote`(창 띄우는 자격 증명 질문 끔). 설정에서 끄면 네트워크를 쓰지 않는다. 실패·오프라인이면 발견 없음.

## Acceptance criteria (v1 완료 기준)
1. 로그인 뒤 Claude Monitor 프로세스 묶음이 하나만 돈다(두 번 실행해도 하나).
2. 상태 막대가 항상 위에 있고, 모니터 멈춤·수집 오류 상태를 보여 준다.
3. 상태 막대를 누르면 브라우저가 아닌 앱 창이 열린다.
4. 최적화 탭이 Claude·Codex 발견을 설명과 함께 보여 준다.
5. Codex 고침(X1)이 미리보기 → 적용(백업 생성) → 되돌리기까지 된다(가짜 `~/.codex` 테스트로 확인).
6. Claude 고침(C1)은 `apply.sh` 실행만 하고 라이브 파일을 직접 쓰지 않는다(테스트로 확인).
7. `bootstrap/setup.ps1 -Only claude-monitor`가 깨끗한 프로필에 설치·자동 시작을 만든다(-DryRun은 출력만).
8. `app/` 핵심(Source·Check·Optimizer) `node --test`와 기존 검사 전부 통과(CI는 Electron 바이너리 없이).
9. reviewer 지적 0건.

## Out of scope (v1)
새 권장 설정 자동 제안, Codex 설정의 다른 고침, 업데이트 자동 실행(U1·U2는 보고만), macOS·Linux, 앱 서명.
