# TRACE v1.3.1 — RTK 라이브 초기 오류 복구

v1.3.0의 최초 HTML 요청은 RTK 집계 실패를 그대로 JSON 503으로 내보냈다.
이미 열린 화면의 재조회에는 이전 값 유지 로직이 있었지만 새로 연 화면에는
적용되지 않았다. 이 패치는 최초 요청에도 보고 템플릿을 유지한다.

- 유효한 저장 집계는 원래 시각과 ‘집계 오류 · 저장된 값 표시’로 표시한다.
- 저장 자료도 없으면 수치·이력은 미확인으로 두며 0이나 현재 성공을 만들지 않는다.
- API는 실패 시 503을 유지한다. 이후 실제 조회가 성공하면 차트·표가 정상 갱신된다.
- 일부 DB 이력 복구 시 현재 실제 DB와 손상 전 스냅샷을 구분한다. 합산이나
  합성 command 기록을 만들지 않는다. 원본 DB와 개인 통계는 ZIP에 포함하지 않는다.

원인은 로컬 RTK DB 손상으로 확인됐으나, 손상이 발생한 과정은 미확인이다.
운영 DB 복구는 원본 보존과 격리 무결성 검사 후 수행하며 서버가 자동으로 DB를
초기화하지 않는다. [공식 SQLite 복구 문서](https://sqlite.org/recovery.html)는
일부 데이터 손실과 복구 결과의 불확실성을 설명한다.

검증은 최초 조회 실패→저장 화면 유지→실제 API 실패→회복 후 성공, 저장 자료
없음→미확인 표시, 비밀 필드 제외 및 기존 일시정지/숨김/실패/동시 조회 방지
검사를 포함한다. 실제 기존 주소의 HTML·API·과거 스냅샷 200 응답과 집계 시각
진행도 확인했다. HTTP/DOM 검사는 현재 공식 브라우저의 화면 검수와 구분한다.

CLI·RTK·Archify·Ponytail 버전, 모델/effort, 훅·권한·인증·일정은 변경하지 않는다.
설치 절차는 [v1.3.0 안내](release-1.3.0.md)와 같으며 최신 ZIP/태그는 v1.3.1을
사용한다. 기존 v1.3.0 태그·ZIP을 교체하지 않고 별도 패치 릴리스로 배포한다.
