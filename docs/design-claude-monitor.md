# Design: Claude Monitor (데스크톱 앱)

소스 (이 문서의 모든 값은 아래 셋 중 하나에서 옴. Figma 없음):
- `S` = `docs/spec-claude-monitor.md` ("Screens", "Visual sources", "Checks v1", "Safety rules")
- `H` = `scripts/monitor-html.mjs`의 `const CSS`와 렌더 함수 (앱 창이 이 페이지를 그대로 씀)
- `B` = `scripts/monitor-bar.ps1` (상태 막대 XAML 값)

프로젝트에 SCSS `abstracts/`가 없어 토큰 이름은 `H`의 CSS 커스텀 프로퍼티(`--bg` 등)를 그대로 쓴다. `fluid()`도 없다(고정 px). "신규"는 소스에 없는 이름이고, 값이 아니라 기존 토큰을 조합한 규칙에만 쓴다. 값이 비어 있는 곳은 `[열림 Qn]`으로 표시하고 문서 끝 "Open questions"에 모았다.

## 2. 상태 막대 (Strip)

### 2.1 배치
창: 테두리 없음, 항상 위, 작업 표시줄 버튼 없음, 너비는 내용에 맞춤(B의 `SizeToContent`), 높이 34. 기본 위치: 작업 영역 오른쪽에서 12, 아래에서 10 띄움 (B의 `Move-Default`).

왼쪽에서 오른쪽 순서 (B와 같음, Codex 한 칸만 추가):

```
[12] ● 상태글자 [12|구분선|12] 라우팅 a/b [16] 오늘 출력 값 [16] 실행 중 세션 N · 에이전트 M [16] Codex ●값 [12|구분선|12] HH:mm [12]
```

| 순서 | 항목 | 보조 글자(`$muted`) | 값 글자(`$fg`) | 앞 간격 |
|---|---|---|---|---|
| 1 | 상태 점 8px + 상태 글자(SemiBold) | – | 상태 글자 | 안쪽 12, 점과 글자 사이 8 |
| 2 | 구분선 1x14 `$sep` | – | – | 좌우 12 |
| 3 | 라우팅 | "라우팅" | "a/b" (total 0이면 "—") | 라벨과 값 사이 4 |
| 4 | 오늘 출력 | "오늘 출력" | 1만 미만 "9,999", 1만 이상 "1.2만", 100만 이상 "123만", 1억 이상 "1.2억" | 앞 항목과 16 |
| 5 | 실행 중 | "실행 중" | 에이전트 0이면 "세션 N", 아니면 "세션 N · 에이전트 M" | 16 |

상호작용 상태:
- 기본: 위 표. 호버: 손 모양 커서만 바뀜(B `Cursor="Hand"`), 색 변화 없음. 눌림: 소스에 없음 → 변화 없음으로 제안 [열림 Q28]. 비활성: 소스에 없음 [열림 Q28]. 에러: 문제 N / node 없음 / 모니터 꺼짐.
- 포커스: B는 마우스 전용이라 키보드 포커스가 없음 [열림 Q5].

- 테마: 시작할 때 한 번 읽음(B). 실행 중 테마 바뀜에 따를지는 [열림 Q6].

### 2.3 클릭·끌기
- 왼쪽 누름 → 끌어서 이동. 누른 곳과 뗀 곳의 차이가 가로·세로 모두 3px 미만이면 클릭으로 보고 Main 창을 연다 (B). 끌었으면 열지 않음.
- 이미 Main이 열려 있을 때 클릭하면 새 창이 아니라 그 창으로 이동 [열림 Q7] (S는 단일 인스턴스만 말함).
- 다른 창이 항상 위 자리를 가져가면 다시 항상 위로 올림 (B `Deactivated`).
- 이동한 위치를 다음 실행에도 기억할지, 모니터 밖으로 나갔을 때 처리: [열림 Q8].

### 2.4 오른쪽 클릭 메뉴
OS 기본 메뉴(소스에 모양 값 없음). 순서와 글자는 S: **열기 · 지금 새로 읽기 · 오른쪽 아래로 · (구분선) · 끝내기**. 끝내기 앞 구분선은 B(닫기 앞)에서 가져옴.
- 열기 = 왼쪽 클릭과 같음. 지금 새로 읽기 = 즉시 다시 읽고 그림. 오른쪽 아래로 = 기본 위치(2.1)로 이동. 끝내기 = 막대와 앱 종료 범위는 [열림 Q9].
- B에 있던 "모니터 다시 시작"은 S 메뉴에 없음 → 툴팁 문구와 충돌 [열림 Q3].
- 메뉴 항목의 호버·포커스·눌림·비활성: 모양 값이 S, B, H 어디에도 없음. OS 기본 메뉴가 그리는 대로 두는 것으로 제안 [열림 Q28].
- 접근 이름: **"Claude 모니터 상태"** (B의 `AutomationProperties.Name`).

## 3. 메인 창 (Main)

- 제목: "Claude Monitor" (S). 작업 표시줄 아이콘 있음 (S). 아이콘 이미지: [열림 Q10].
- 기본 크기 1280 x 860 (B의 `--window-size=1280,860`, 지금 쓰는 앱 창과 같음). 최소 크기: [열림 Q11].
- 페이지 안 제목(`h1`)은 지금 "클로드 설정 모니터"(H). 창 제목과 다름 [열림 Q12].
- 화면: H의 페이지 그대로. 위 `header.top`(제목·탭·실시간 표시·테마 버튼) 아래 `main.stage`(`.view` 하나만 보임).

| 창 너비 | 모양 |

| 1240px 이상 (기본 1280 포함) | 위 줄 한 줄: 제목 / 탭 / 메타. `.view` 최대 폭 1200 |

### 3.2 탭 줄
기존 7개 순서는 그대로, 뒤에 "Codex", "최적화"를 붙인다 (S가 말한 순서). 최종 9개:
개요 · 구조 · 오케스트레이션 · 모델 라우팅 · 토큰 · 절감 효과 · 설정 상태 · **Codex** · **최적화**
- 단추는 기존 `.tabs button` 그대로: 글자 `--t-sm` `--muted`, 높이 32(1239px 이하 40), 반경 `--r-sm`, 안쪽 좌우 `--sp-3`.
- 상태: 기본 `--muted` / 호버 `--fg` / 선택(`aria-current="page"`) `--fg`, weight 500, 바탕 `--raise` + 1px `--line` 링 / 포커스 `:focus-visible` 2px `--accent`, offset -2 / 눌림·비활성·에러: 소스에 없음. 탭은 항상 눌릴 수 있다고 보고 별도 모양을 두지 않는 것으로 제안 [열림 Q28].
- 최적화 탭에 발견 건수 배지를 달지는 [열림 Q13].

## 4. 최적화 탭 (`id="opt"`, `section aria-label="최적화"`)

기존 `.view`(세로 `--gap`) 안에 패널 하나. 열 구성은 한 열. KPI 띠는 쓰지 않는다(발견 건수는 패널 안내에 표시).

패널: `.panel` / 제목 `.ph h2` "발견 목록" / 안내 `.ph .hint` "발견 N건" (S의 "발견 0건"에서 가져온 표현). 본문은 `.pitems` 안의 `.fnd` 목록. 정렬: 심각도 높은 순, 같으면 점검 번호 순(C1…X3) [열림 Q14].
